# 三亚旅行计划网页 · 信息架构与页面结构设计

> 目标：Mobile First 单页静态网页，微信群内分享，**2 人**（本人 + 1 位同行）随时查看整个旅行计划。
> 数据源：`travel-data.json`
>
> **已确认的三项决策**：① 单日详情用手风琴原地展开；② 同行人共 2 人（与两家住宿各 1 间房一致）；③ 每日行程先按「骨架 + 待定占位」开发，内容后补。

---

## 一、设计前提与核心决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 页面形态 | **单页纵向滚动**（Single Page，无路由） | 微信内置浏览器的返回行为不可控；分享链接必须一打开就是完整计划，不能落在子页 |
| 导航 | **顶部吸顶 segmented tab**，点击锚点平滑滚动 | 底部 tab bar 会和微信底部工具条视觉冲突 |
| 单日详情 | **原地手风琴展开**（accordion，已确认），展开后自动滚动到卡片顶部 | 保留时间轴上下文，无需路由；比全屏抽屉更少交互层级 |
| 同时展开 | 只允许展开 1 天（互斥），再点收起 | 避免页面无限变长 |
| 状态管理 | 纯静态 + 客户端计算（今天是第几天、倒计时、航班是否已过） | 无后端，链接永久可用 |
| 登录/权限 | 无 | 群内分享，人人可看 |

### 微信环境约束（必须遵守）
- 正文字号 ≥ 14px，标题不小于 17px；触控区 ≥ 44×44px
- 地图 URL scheme 在微信内经常被拦截 → **每个地址必须同时提供「复制地址」兜底按钮**
- 页面 `<title>` 决定微信分享卡片标题；首屏需有一张可被抓取的主图
- 首屏渲染资源尽量内联，弱网下 1 秒内出内容
- 全站单向纵向滚动，只有航班卡是横向滑动（且要有明显的「露出下一张」暗示，避免用户不知道能滑）

## S0 · Hero 标题区（首屏）

**内容**
- 主标题：`三亚 6 天 5 晚`
- 副标题：`上海 ⇄ 三亚`
- 日期：`2026.09.22 – 09.27 · 周二至周日`
- 目的地：`中国 · 海南 · 三亚` ／ 地点标签 `亚龙湾` `天涯镇马岭`
- 数据徽章条：`6 天` `4 晚住宿` `2 段航班` `2 人`
- **旅程倒计时**：大号 `D-11` + 文案「距出发还有 11 天」

**状态变化（客户端按当前日期计算）**
| 时机 | 显示 |
|---|---|
| 出发前 | `距出发还有 X 天` |
| 出发当天 | `今天出发 ✈️` |
| 旅途中 | `旅程进行中 · 第 3 / 6 天` |
| 结束后 | `旅程已结束` |

**视觉**：三亚海景背景图 + 深色渐变蒙层保证文字对比度；高度约 60vh，底部露出航班卡上沿以引导下滑。

> 倒计时分工：Hero = **整段旅程**倒计时（按天）；航班卡 = **该趟航班**倒计时（到分钟）。两者语义不同，不算重复。

## S1 · 航班信息（需求 2）

### 布局
横向 **scroll-snap** 轮播，一屏一张大卡（宽约 88vw，右侧露出 8vw 下一张边缘），下方页码圆点 `● ○`。

- 卡片数量：当前 2 张（去程 / 返程），结构上支持 N 张
- **首次进入默认定位到「下一趟即将起飞」的航班**（出发前 = 去程；到 09-25 后自动定位到返程）
- 已起飞的航班：整卡降饱和度 + 右上角「已完成」角标，但仍可滑回查看
- 本期按**一个人（我）的航班**渲染；共 2 人同行，若两人航班一致则卡片直接复用，无需区分乘客

### 单卡内容（登机牌样式）
```
┌──────────────────────────────────┐
│ 去程                    已出票 ● │
│ 东方航空  MU5397                  │
│                                   │
│  21:30            3h40m     01:10 │
│  PVG          ✈ ---------      SYX│
│  上海浦东                 三亚凤凰 │
│  T1 航站楼            次日 +1     │
│                                   │
│  09-22 周二                       │
│ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─│
│  ⏱ 距起飞 10 天 04:22:15          │
│  ¥549 · 优惠券 / 购物券           │
└──────────────────────────────────┘
```

**字段映射**（← `flights[]`）
| 展示 | 字段 |
|---|---|
| 去程/返程 | `direction` |
| 航司 + 航班号 | `airline` + `flight_no` |
| 起降时间 | `depart_time` / `arrive_time` |
| 机场三字码 + 中文名 | `depart_airport` / `arrive_airport` |
| 航站楼 | `depart_terminal` |
| 跨天标记 `+1` | `overnight === true` |
| 时长 | `duration` |
| 倒计时基准 | `depart_date` + `depart_time` |
| 价格 / 赠送 | `price` / `included_services` |
| 状态 | `status` |

**倒计时规则**：`天 时:分:秒`，每秒刷新；进入 24 小时内切换为强调色 + 文案「即将起飞」；起飞时刻后显示「已起飞 / 已完成」并停止计时。

**待补数据**：返程 9C8780 抵达上海的机场（浦东 / 虹桥）未知 → 先显示 `上海`，标注「以出票短信为准」。

## S2 · 每日行程

### ① 总览时间轴（需求 3-①）

竖向时间轴，左侧一根连续轴线 + 6 个节点，每节点一张可点击的**折叠卡**：

```
●─┐ DAY 1  09-22 周二
  │ 上海 → 三亚（夜间飞行）
  │ ✈️ MU5397 21:30    🛏 夜间航班·无住宿          ⌄
  │
●─┐ DAY 2  09-23 周三          ← 换住宿
  │ 抵达三亚 · 亚龙湾
  │ ✈️ 01:10 落地  🏨 亚龙湾喜来登  📍3 项安排      ⌄
  │
●─┐ DAY 3  09-24 周四
  │ 三亚 · 亚龙湾
  │ 🏨 亚龙湾喜来登  · 行程待定                     ⌄
  ⋮
```

**每张卡的信息层级**
1. `DAY n` + `日期` + `周几`（← `day` / `date` / `weekday`）
2. **地点路径**：`location_label`（"从哪里到哪里"，这是总览的核心信息）
3. 摘要 chips：航班（有则显示航班号+时间）／今晚住宿名／`activities` 数量
4. 右侧展开箭头

**节点状态**
| 状态 | 视觉 |
|---|---|
| 今天 | 节点实心放大 + 主色描边 + 「今天」标签 |
| 已过去 | 节点空心、文字降透明度 |
| 未来 | 常规 |
| 换酒店日（D4） | 加 `换住宿` 橙色小标 |
| 跨城/机场日（D1、D6） | 加 `✈️` 强调 |

### ② 单日详情（展开态，需求 3-②）

展开后在卡片内渲染**分时段子时间轴**，事件按时间升序：

```
  22:00  🚕  出发前往浦东机场
  21:30  ✈️  MU5397 上海浦东 T1 起飞
         └ 上海浦东国际机场 T1   [导航] [复制地址]
```

**单条事件的结构**
- `时间`：`HH:mm`，无时间的事件不编造 → 归入底部「当天待定 / 全天」分组
- `类型图标`：`flight ✈️` `transfer 🚕` `hotel 🏨` `activity 📍` `meal 🍽` `free ☀️`
- `标题`：`event.title`
- `地点行`：地点名 + 地址（← 需在 JSON 中补 `event.location`）
- **操作**：`[导航]`（高德/腾讯地图 URL）+ `[复制地址]`（微信内兜底，必须有）
- `备注`：`note`（如「红眼航班，提前联系酒店 late check-in」）

**当天固定信息条**（置于详情顶部）
- `今晚住：亚龙湾喜来登 · 全海景客房`（点击跳 S3 对应住宿卡）
- 可选：`天气占位`

**空状态（本期采用：骨架 + 占位）**：`activities` 为空的天，详情区只渲染已确定的航班/住宿/接驳事件，并在末尾追加占位条：
> 🗓 当天行程待定 —— 出发前补充

- D1 / D2 / D4 / D6：有航班、住宿、接驳事件 → 时间轴有内容 + 底部占位条
- D3 / D5：完全无事件 → 整个详情区为占位空态（仅显示「今晚住 XX」+ 占位条）
- 占位条样式：虚线边框 + 灰色文字，明确表达「未安排」而非「加载失败」
- 后续补 `activities` 时前端零改动，占位条在该天有活动后自动隐藏

## S3 · 住宿信息

2 张卡（← `hotels[]`），每张包含：
- 名称 + 区域标签（`亚龙湾` / `天涯镇马岭`）
- **日期条**：`09-23 → 09-25 · 2 晚 · 1 间`，并标注覆盖 `DAY 2–3`
- 房型：`全海景客房` / `晓梦-270°海景阳台`
- 地址 + `[导航] [复制地址]`
- 价格 + 支付方式徽章：喜来登 `在线担保 · 到店付 ¥3042`（**橙色警示色**，需现场支付）／民宿 `已在线付 ¥1218`（灰色）
- 状态 `预订成功`
- 待补：酒店电话（有了就加 `[打电话]`）

> ⚠️ 喜来登金额待核对：截图为 `到店付 ¥3042`，文档批注写的是 `3402`，且「在线担保 + 到店另付」是否为两笔支出未定。当前按 **¥3042、担保不实扣、到店支付一笔** 计入费用汇总。

## S4 · 交通与接送

- 3 段接驳（← `transport.local_transport[]`），每条显示：日期 / 类型 / 起终点 / 距离时长 / 备注
- 全部加 **`待确认` 虚线边框徽章**，明确区分「已订」与「推算建议」，避免同行人误以为已安排好
- `car_rental` 与 `trains` 为空 → **该子块直接不渲染**，不显示空壳

## 三、travel-data.json 需要新增的字段

| 字段 | 说明 | 优先级 |
|---|---|---|
| `travelers.count = 2` | 已确认 2 人 | ✅ 已定 |
| `events[].location` | 现有 events 缺地点对象，`[导航]/[复制地址]` 依赖它 | ⭐ 开发前需补 |
| `itinerary[].activities[]` | 每天分时段安排，结构 `{time, type, title, location:{name,address,lat,lng}, note, duration}` | 本期留空，出发前补 |
| `hotels[].phone` / `coords` | 打电话、导航 | 建议 |
| `hotels[0].payment` | 喜来登「在线担保 + 到店付」金额待核对 | 需确认 |
| `reminders[]` | S5 提醒内容结构化，避免硬编码在 HTML | 建议 |
| `weather` | 每日天气占位（可留空） | 可选 |

> 约定：所有"推算/未确认"数据统一带 `confirmed: false`，前端据此渲染 `待确认` 徽章。这样内容和展示解耦，后续改数据不用改代码。
>
> `activities` 留空是本期的**有意设计**，不是缺陷：页面先把骨架和占位跑通，内容后填即可，前端不需要二次改动。
